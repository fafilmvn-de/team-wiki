# ADR 0010 — Solo (focus) mode in the mini-wiki Domain map

Date: 2026-05-22
Status: Accepted
Supersedes: —
Superseded by: —

## Context

The mini-wiki page `semantic/08_Semantic_Model.html` (generated by
`scripts/build_semantic.py`) renders the model as an SVG Domain map.
Clicking a domain *already* reveals its satellites and highlights its
edges — but every domain stays in place, so when a domain has many
tables (e.g. `DASHBOARD`, 29 tables in `semantic.json` as of 2026-05-22),
its ring of satellite bubbles overlaps neighbouring domains and is
difficult to read.

Earlier this week we shipped **Solo mode** in the Semantic Editor
(ADR 0009): clicking a domain pulls it to the canvas centre, satellites
get their full labels, and the other domains collapse to dimmed "ghost
pucks" on the perimeter. The user asked to port the same affordance to
the read-only mini-wiki, with a trimmed scope.

## Decision

Add Solo focus mode to the mini-wiki Domain map with **a deliberate
subset of the editor's behaviour**, inlined into `build_semantic.py`'s
template (no new asset files).

Behaviour shipped:

- Click a domain → enter Solo. The focused puck translates to the
  canvas centre via two new CSS custom properties `--sdx` / `--sdy`
  composed with the existing `--ndx` / `--ndy` nudge translation. The
  other domains translate to a perimeter inset ring; they receive a
  `.is-ghost` class (dimmed opacity 0.55, dashed border, table count
  hidden).
- Edges not touching the focused domain receive a `.solo-hidden` class
  (`display: none`). Visible edges have their endpoints recomputed to
  follow the new domain positions.
- The focused domain's satellites are revealed via the existing
  staggered animation; per-table offsets from `meta.solo_offsets`
  (written by the editor) are honoured when present.
- Exits: empty-canvas click · `Esc` · `← All domains` breadcrumb chip ·
  switching to Table-model view.
- Public surface for tests: `window.__wiki = { enterSolo, exitSolo }`.

Behaviour deliberately **not** ported from the editor:

- **Dots-only overview** with aggregated inter-domain edges and a
  zoom-threshold label reveal. Wiki readers expect the existing labeled
  satellite rings on first load; only the *focus* step is new.
- **`⌬ Tidy` chip** — adaptive ring/spiral re-layout. Authoring affordance.
- **Drag-to-persist** satellite offsets. Wiki is read-only; persistence
  has no Save path.

## Alternatives considered

1. **Port everything from the editor unchanged.** Rejected: the
   dots-overview changes the wiki's first-load UX for every reader, not
   just the ones who hit a crowded domain. The friction outweighs the
   benefit. Tidy and drag-persist are authoring features.

2. **Hide non-focused domains entirely in Solo (no ghost pucks).**
   Rejected: loses one-click navigation between domains. Browsers would
   have to exit Solo, then click another puck. Ghost pucks are cheap
   (~20 lines of math) and turn the Domain map into a navigable
   focus-and-fan-out interface.

3. **A small domain-switcher chip row instead of ghost pucks.**
   Rejected: chips break the spatial intuition that ghost positions
   preserve (a domain that was north-east of the focused one stays
   north-east). On a model with 8+ domains the spatial cue matters.

4. **Extract a shared `assets/solo_mode.js` module reused by both the
   editor and the wiki.** Rejected: the editor's Solo helpers depend on
   `STATE` / `markDirty` / `Save` plumbing that doesn't exist in the
   wiki. A shared module would need a non-trivial refactor for ~250
   lines of duplication, and the wiki page is consumed as a stand-alone
   single-file artifact (per ADR 0005). Inlining keeps the wiki
   zero-dep.

## Consequences

- Reader UX: the crowded-Dashboard problem resolves on click —
  centered, readable, with the other domains still discoverable on the
  perimeter.
- Authoring: edits to `meta.solo_offsets` in the editor visibly carry
  through to the published wiki (the same per-table offsets apply when
  that domain is soloed). One-way; the wiki cannot write back.
- Tests: `scripts/smoke_mini_wiki_solo.py` (new, 6 sub-checks) verifies
  the API surface, class transitions, CSS-var translation, edge
  visibility filter, focus switching, and exit cleanup.
- Build: inline addition; no new asset files, no `rebuild_wiki.py`
  changes needed.
- Risk: changing the click semantic for domain bubbles. Mitigation:
  existing `selectDomain` behaviour is preserved (still highlights
  edges, reveals satellites, renders side panel); Solo state is layered
  on top, exits are abundant.
