01

What is this?

A one-page, self-contained directory of every analytical workstream a team owns.

The main wiki (index.html) is a single static HTML file that lists every project, campaign, model, BAU procedure, strategy doc, and adhoc deliverable the team currently owns or has handed off. Think of it as a Wikipedia article whose subject is "the team's work" — every entry links out to the underlying notebook, SharePoint folder, Word manual, or deep-dive sub-page.

One source of truth: the whole page is rendered from a single JSON file (handovers/inventory.json) by a Python build script. To change what appears in the wiki, you change that JSON — not the HTML.

The six categories

Every row in the wiki belongs to exactly one of these:

strategic recurring annual / strategy regular

Every bucket gets a numeric ID (PRJ-2025-01, BAU-2019-03, …) that survives across years even when the project name changes. IDs are how the wiki cross-references itself.

02

Page anatomy

Three regions: the persistent sidebar (left), the filter strip (top), and the section grid (centre).

  1. 1Sidebar. Numbered index of all 11 sections. Scroll-spy highlights the section you're currently viewing in clay-orange. Click to jump.
  2. 2Filter chip strip. Three groups (Tier · Status · Year) separated by faint dividers. Chips combine with AND; the year list is auto-derived from the data.
  3. 3Hero counts. Live totals — buckets, adhoc deliverables, open items. Refreshed on every rebuild.
  4. 4Card grid. Auto-fitting grid (3 cols on desktop, 2 on tablet, 1 on phone). Every card links out to its source notebook, SharePoint folder, or deep-pack sub-page.
  5. 5Clay-orange left stripe. Visual cue for Tier=P0 or Status=Active — your eye lands on it first.
03

How to read it

Three reading modes for three audiences.

Mode 01
Browsing
Just scroll. Each section (§01 Projects, §02 Campaigns, …) is a self-contained grid of cards. Click any card to jump to the source notebook, SharePoint folder, or deep-dive sub-page.
Mode 02
Filtering
Use the chip strip at the top: Tier (P0/P1/P2), Status (Active/Completed/Superseded/Retired), Year (auto-derived). Chips combine with AND. Clear all with one click. The Retired chip is the fast way to see only the Archive rows across all categories.
Mode 03
Searching
Use the browser's Ctrl+F. The page is a single static HTML — keyword search just works, no server roundtrip.

Card anatomy

Every card carries the same elements in the same order — left to right, top to bottom:

  • Eyebrow — the bucket ID in clay-orange mono.
  • Title — human-readable name (serif).
  • Meta strip — tier + status + year pills.
  • Purpose — one-sentence description.
  • Links — GitHub repo path · SharePoint folder · deep-pack (when present).
Visual cues: a 3-pixel clay-orange left border means Tier=P0 or Status=Active. A soft shadow means the bucket has a per-project deep-pack at §09. A small footer thumb means the card opens a full mini-wiki.
04

How to maintain it

Three commands and a local admin page. No SharePoint List, no Power App.

source of truth generated artifact tool / terminal

The 60-second loop

# 1. Boot the loopback admin server (no firewall prompt)
python handovers/serve_admin.py

# 2. Browser opens automatically at localhost:8765/admin.html
#    Six tabs · edit inline · validation · soft-delete via Status=Retired
#    Ctrl-S to save (the server writes inventory.json + rotates .bak)

# 3. Rebuild
python handovers/scripts/rebuild_wiki.py

# 4. Eyeball index.html, then commit
git add handovers/inventory.json handovers/index.html handovers/CHANGELOG.md
git commit -m "wiki: "
git push
Two ways to remove a row, and they are not the same.
  • Soft-delete (recommended) — change the row's Status dropdown to Retired. The row drops out of its live category section (Projects / Campaigns / …) and the main sidebar count, but it still renders in the wiki's Archive section — a muted, category-grouped table of retired buckets so newcomers can still search, find, and read about obsolete work. The repo ↔ bucket map also keeps the row so cross-references stay complete. Toggle show retired in the admin to bring it back into the editor; flip Status to Active / Completed to fully restore it.
  • Hard-delete — click the row's Delete button. This permanently removes the row from inventory.json (along with any linked narratives, mini_wikis, and sp_overrides entries). Use only if the row was created in error. The previous file is kept as inventory.json.bak.

For the full reference — allowed values, ID conventions, troubleshooting, cadence — read MAINTENANCE.md.

05

Fork it for your team

The same six categories work for any analytics function. Stand up your own AI Wiki in five steps.

Step 01
Clone or copy
Fork the repo, or just download the handovers/ folder into your own repo. Self-contained: only Python stdlib + (optional) Playwright for UAT.
Step 02
Edit the starter inventory
A pre-seeded inventory.json ships with one example row per category (6 buckets, 2 adhoc, 2 open items). Edit it directly or wipe it and start blank.
Step 03
Add your buckets
Launch serve_admin.py, edit in the browser. Soft-delete the samples, add your own. Update _meta.owner in the JSON.
Step 04
Edit narratives (optional)
Per-bucket "Decisions baked in" and "Open questions" live inside inventory.json under narratives. Edit via the 📝 button in admin.html. Skip this if you don't have deep packs.
Step 05
Build & publish
rebuild_wiki.py renders index.html. Commit + push; if GitHub Pages is on, your site is live in 5–10 minutes. Or just open the HTML locally.
Step 06
Rebrand (optional)
Find/replace the wiki title (default The Team AI Wikipedia) and the sidebar brand (Team · AI Wiki) in step11_build_wiki.py and admin.html. ~5 occurrences total.

What stays the same vs. what changes

Stays the same

  • The six categories — Project · Campaign · Model · BAU · Strategy · Adhoc.
  • ID conventions — PRJ-YYYY-NN, ADH-YYYY-NNN, etc.
  • Allowed statuses — Active · Completed · Superseded · Retired.
  • The Birchline design system — palette, type scale, card variants.
  • Build pipeline — init → admin → rebuild.

You change

  • The rows under each category — your projects, your campaigns.
  • The actual IDs you assign (the format stays the same).
  • Which status each of your rows is in.
  • The brand title + your team's name (~5 occurrences in 2 files).
  • Your SharePoint root — search SP_ROOT in step11_build_wiki.py.

07

Tips & shortcuts

Small things that make daily reading and editing faster.

Reading
Ctrl+F searches the whole page — IDs, names, purposes, all of it. There's no separate search box because there doesn't need to be one.
Filtering
Chips at the top of index.html stack (AND). Click an active chip again to deselect. The "All" pseudo-chip clears the group.
Editing
Ctrl+S saves from admin.html. Esc closes the add-row modal. The browser-tab title flips to "• unsaved" when there are pending changes.
Validation
Rows with a red gutter are blocked from saving. Hover the row to see why (ID prefix mismatch, malformed year, bad date format).
Undo a bad save
The server rotates inventory.json.bak before every write. To roll back: stop the server, copy .bak over inventory.json, restart.
Adhoc dates
Any edit on an adhoc row auto-stamps last_touch to today's date. You never set it by hand.
Year chips
The year filter chips on index.html are auto-derived on every rebuild from the data. Adding a 2027 bucket automatically adds a 2027 chip next rebuild.
Mobile
Sidebar collapses to a top strip below 1100 px. All sections stay readable on a phone.
